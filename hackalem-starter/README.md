# HackAlem AI — стартовый каркас (трек «Креативные индустрии»)

Заготовка на Python, чтобы не тратить время хакатона на бойлерплейт. Реальный
кейс объявят только в день хакатона — этот каркас нарочно не завязан на
конкретную задачу: меняешь несколько мест (отмечены ниже) и адаптируешь под то,
что дадут.

## Стек
- **FastAPI** — бэкенд/API.
- **OpenAI SDK** (`openai` пакет) — чат + function calling + structured outputs.
- **SQLite** — хранилище (встроено в Python, ставить не нужно).
- **Чистый HTML/JS** — фронтенд для быстрой проверки, без npm/React/сборщиков.

## Структура
```
backend/
  config.py          настройки из .env
  db.py              SQLite: история чата + универсальная таблица "items"
  logging_utils.py   лог каждого вызова OpenAI в logs/calls.jsonl
  openai_client.py   обёртка над OpenAI: ретраи, фолбэк-модель, structured outputs
  tools.py           "инструменты" для function calling (сейчас — заглушка save_note/search_notes)
  agent.py           цикл агента: модель <-> вызовы инструментов <-> модель
  main.py            FastAPI-приложение, роуты, отдача фронтенда
frontend/
  index.html         простой чат для проверки агента в браузере
tests/
  test_smoke.py       быстрая проверка, что всё поднимается (без реального API-ключа)
```

## Установка и запуск

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. Поставить зависимости
pip install -r requirements.txt

# 3. Настроить ключ
cp .env.example .env
# открой .env и впиши OPENAI_API_KEY (выдадут на хакатоне)

# 4. Запустить сервер
uvicorn backend.main:app --reload
```

Открой http://localhost:8000 — там простой чат. Напиши агенту что-то вроде
«сохрани заметку: нужно сделать логотип» — он вызовет `save_note`, а строку
«найди заметки про логотип» — вызовет `search_notes`. Это проверяет, что вся
цепочка (модель → вызов функции → SQLite → ответ) реально работает.

Без API-ключа сервер тоже поднимется (фронтенд откроется), но `/api/chat`
будет падать с ошибкой — это ожидаемо.

### Проверка без API-ключа
```bash
python -m pytest tests/
```
Дымовой тест не трогает OpenAI API — только что сервер и роуты живы.

## Что менять, когда объявят кейс

1. **`backend/agent.py` → `SYSTEM_PROMPT`** — опиши задачу словами: кто
   пользователь, какую проблему решаем, что должен делать агент.
2. **`backend/tools.py` + `TOOLS_SCHEMA`/`TOOLS_IMPL` в `agent.py`** — замени
   `save_note`/`search_notes` на функции под реальный кейс (генерация
   контента, поиск ассетов, перевод, что угодно). Схема (JSON) в `agent.py`
   должна совпадать с сигнатурой функции в `tools.py`.
3. **`backend/db.py`** — если нужны новые сущности, добавляй такие же
   функции-хелперы (`add_item`/`list_items` уже универсальны под любой
   `item_type`, скорее всего менять схему не придётся вообще).
4. Если понадобится вернуть данные в строгом формате (не текст, а JSON с
   конкретными полями) — используй `structured_completion()` из
   `openai_client.py` вместо `chat_completion()`, передав pydantic-модель.

## На заметку
- Правила HackAlem AI требуют использовать **Codex во время разработки** —
  это отдельный инструмент (openai.com/codex), каркас с ним никак не связан,
  просто не забудь запускать его в процессе.
- `OPENAI_MODEL`/`OPENAI_FALLBACK_MODEL` в `.env` — если на хакатоне выдадут
  доступ к конкретным моделям, поменяй значения там, а не в коде.
- Логи всех вызовов OpenAI пишутся в `logs/calls.jsonl` — полезно для отладки
  и как доказательство работы интеграции для жюри.
- `hackathon.db` (SQLite-файл) создаётся автоматически при первом запуске —
  в `.gitignore` он уже исключён.
